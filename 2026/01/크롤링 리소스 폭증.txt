* Golang 크롤링 브라우저, 페이지 리소스 폭증 현상
- AP mgmtIp 별 크롤링 browser, pagePool이 분리되어있는 상황
- 이로 인해, 현장 site AP 장비 1000대가 붙었을때 리소스 폭증 현상 발생 제기
- 아래 잠재적 오류 확인
  1) 브라우저 프로세스 과다 생성(AP 단위 Browser 생성) → CPU/RAM/FD 폭증
  2) 동시 Rod Page 폭주 → 타임아웃/세션 꼬임/메모리 누수

* 해결안 제시
- 1차적으로 AP 모델별로 browser 분리 (현장 모델 종류 12개 = browser 12개 운영)
- 하나의 browser 내에서 5~10개의 pagePool로 관리
- pagePool은 같은 모델끼리 공유 자원으로 사용 (동시 처리 제한)
